# Kvindo Cloud Provider

The Kvindo Cloud provider lets you manage [Kvindo Cloud](https://cloud.kvindo.com) infrastructure
as code. It talks to the same REST API as the [web console](https://cloud.kvindo.com) and the
[`kc` CLI](https://github.com/Kvindo/kc-cli), so anything you can provision in the console you can
declare in Terraform.

Supported resources include virtual machines (VMs), block volumes, floating IPs, S3 object
storage, Kubernetes clusters and node groups, load balancers, security groups, route tables, VPCs
and VPC peering, VPNs (OpenVPN), managed PostgreSQL, GitLab, monitoring (VictoriaMetrics), billing,
and IAM (users, tokens, access policies).

## Requirements

- [Terraform](https://developer.hashicorp.com/terraform/downloads) >= 1.0
- A Kvindo Cloud account and an API token (set `KVINDO_TOKEN`, or pass `token` in the provider block)

## Installation

```terraform
terraform {
  required_providers {
    kvindo = {
      source = "kvindo/kvindo"
    }
  }
}
```

## Example Usage

```terraform
provider "kvindo" {
  token = var.kvindo_token
  # endpoint = "https://cloud-api.kvindo.com"  # optional, this is the default
}

variable "kvindo_token" {
  description = "Kvindo Cloud API token"
  type        = string
  sensitive   = true
}
```

The API token can also be supplied via the `KVINDO_TOKEN` environment variable, and the endpoint
via `KVINDO_ENDPOINT` (defaults to `https://cloud-api.kvindo.com`).

### Authenticating via a `kc` CLI profile

If you already use the [`kc` CLI](https://github.com/Kvindo/kc-cli) and have run `kc login`, you
can point the provider at a named `kc` profile instead of copying its token into your Terraform
config:

```terraform
provider "kvindo" {
  cli_profile = "prod" # reads ~/.kc/config/prod.yaml, written by `kc login`/`kc switch`
}
```

`cli_profile` can also be set via the `KVINDO_CLI_PROFILE` environment variable. It only fills in
`endpoint`/`token` when they aren't set directly (by attribute or by `KVINDO_ENDPOINT`/
`KVINDO_TOKEN`), so it's safe to leave in a shared config while overriding credentials per-shell
when needed.
